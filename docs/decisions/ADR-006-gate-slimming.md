# ADR-006: 闸内工序减配 —— 去自评/Critic、去 E2E 入库要求、去截图

- 状态：已接受
- 日期：2026-09-24
- 来源：agentory `ADR-003`（用户裁决 2026-09-24：「把设计阶段的自评和 critic 去掉吧，build 阶段的 e2e 也去掉」「把工作流中的截图都去掉」）；数据样本：agentory team-page-redesign（A 级，Build 期 E2E 首跑 15/21 的返工全部为环境/断言踩坑，与功能正确性无关）

## 背景

上游 agentory 复盘（承接 ADR-005 验证分层的同一条思路——把重的验证放在迭代频繁的位置）发现三块纯开销工序：

1. **两段式自评 + fresh-session Critic** 是 Design 阶段最大耗时：三档截图逐张目检 + 质量锚逐条自查 + 另开评审会话。实测中用户对 A 级 feature 直接免 Critic，流程照走通且质量未降——第一眼质量的真正兜底是 design-lint 机械闸 + 人闸肉眼。
2. **Build 期配套浏览器 E2E** 是 Build 阶段最大耗时：套件写作 + 首跑踩坑（CDP 仿真、环境变量、断言标的选择）与功能正确性无关，且 ADR-005 已把全量行为验证定位在 main 兜底层——开发期再写再跑等于双重成本。
3. **截图**贯穿全流程（原型自评截图、Critic 观感截图、PR 贴图、Accept 生产截图目检）——agent 拍图贴图看图全是等待与返工点，而人想看效果直接打开预览链接即可。

## 决策

1. **原型闸工序减为**：组件覆盖检查 → 画变体 → design-lint 0 error → 预览链接送人闸。两段式自评与 Critic 从引擎默认流程**移除**；工序分级表删「截图自评」「Critic」两列（变体数要求保留：门面级首轮 ≥2）。
2. **B 级快速道预授权条件相应减为两条**（原四条）：design-lint 0 error + 变体间无方向性分歧。
3. **Build 期不再要求配套浏览器 E2E suite**（原 ADR-002 第 5 条「Builder 写、缺 suite 即返工」废止该强制项）。若项目有 E2E 库，保留为 **main 回归兜底资产**（ADR-005 L2 层）；「缺 suite」不构成返工项，既有 suite 断言仍受维护。
4. **工作流不产截图**：原型送闸/PR 人闸材料 = 预览链接（链接替代贴图）；Accept AC 取证手段 = API 直打 / 单测 / 亲测（删「截图路径」位）；人感判断 = 人开预览链接/本地环境亲测。E2E 内部的 shot 辅助保留为 main 回归失败时的调试定位手段，非准出材料。
5. **不变项**：design-lint 机械闸（Layer 1）、组件覆盖检查、Brief/原型两道人闸、`prototype_before_build` 等机械闸、Accept 分级取证、S 级人审——删的是「agent 自查自看」的评审工序，不是防跑偏的硬闸，更不是人闸本身。

## 后果

- A 级单 feature 实测预计省 1–2 个会话（自评/Critic/套件写作/首跑踩坑全免）；预览链接秒开，人闸材料反而更直接。
- 风险与对冲：原型第一眼问题后移到人闸/PR 由人发现（打回成本 = 原型重做一轮）；纯前端无单测的行为靠人闸亲测 + main 回归兜底（ADR-005 既有路线）。
- 撤回方式：引擎文档恢复对应用户/项目可按 ADR-003（agentory 版）自行加回；机械闸不受影响。

## 对项目升级的影响

引擎默认不再带「自评/Critic/E2E 入库/截图」要求；已按旧默认运行的项目（如 agentory ADR-002 第 5 条）升级引擎后在项目附录自行裁决保留与否。
